MCP Server

ContextGraph exposes its knowledge graph to AI agents over the Model Context Protocol (MCP) via stdio. Start the server with:

Terminal
./gradlew :modules:cli:installDist
modules/cli/build/install/contextgraph/bin/contextgraph serve-mcp

Claude Desktop

Point the client at the installed launcher rather than at Gradle — an MCP client starts the server on every session, and a Gradle daemon start on each call is pure latency.

claude_desktop_config.json
{
  "mcpServers": {
    "contextgraph": {
      "command": "/absolute/path/to/context-graph/modules/cli/build/install/contextgraph/bin/contextgraph",
      "args": ["serve-mcp"]
    }
  }
}

Tools

The server registers 12 tools. explore is the primary entry point. impact_analysis and trace answer call questions from the resolved call graph. The rest are secondary and mostly return pointers you then follow with a separate file read.

contextgraph.explore — primary

Answers a natural-language question about the codebase in one call. Returns the modules that matched and the relevant symbols, ranked, each with its location and why it ranked.

Ranking. Candidates come from the full-text index — the whole question, each word, and each pair of adjacent words — plus the call-graph neighbours and enclosing classes of the best matches, so the next step of a flow is found even when its name shares no word with the question. Each candidate is scored on how well its name matches the question words (whole identifier words over substrings, rare words over common ones, adjacent word pairs in order, a bonus when the question names it outright; values and fields count for less than classes and functions), on its resolved edges, and on its links to the other strong matches. Symbols from test sources rank after production code unless the question mentions tests.

Detail. "pointers" (the default, 4,000-token budget) gives every symbol its location, why it ranked, up to three callers (calledBy) and callees (calls) as File.kt#Scope.member(), and how many symbols depend on it (dependents); only the top two carry verbatim source, cut to 60 lines (sourceTruncated). Read the files you need from the locations given. "full" (15,000-token budget) gives every symbol that fits its verbatim source, up to 20 resolved edges — each with its confidence and the resolution rung that produced it — and its whole blast radius.

The response is capped at the token budget, measured on the compact JSON it is sent as, at four characters per token. Symbols past it carry location only and are marked "elided": true; symbols that would not fit even elided are left out. estimatedTokensUsed is the size of the response itself, and truncated is true whenever anything was elided or left out. A question that matches nothing returns "empty": true rather than an error.

Prefer this over every tool below for most questions. It exists because agents choose badly among many similar tools and chaining thin calls costs more than one call.

ParameterTypeRequiredDescription
questionstringyesNatural-language question about the codebase
detailstringnopointers (default) or full
tokenBudgetnumbernoMax size of the encoded response in tokens, at four characters per token (default: 4000 for pointers, 15000 for full)

ParameterTypeRequiredDescription

contextgraph.search_nodes

Finds symbols by name or description and returns one line per hit, best first, with its file:line.

Ranking is the same as explore's:

  • identifier words over substrings, and rare words over common ones;
  • classes and methods over constants;
  • links to the other matches count;
  • production code comes before tests unless the query mentions tests.

Each name it shows can be passed straight to trace or impact_analysis as symbol. A types filter, or a query no symbol matches, falls back to plain full-text search across all nodes.

ParameterTypeRequiredDescription
querystringyesSearch query
typesstringnoComma-separated node types e.g. Class,Function
minConfidencenumbernoMinimum confidence 0–1 (default: 0.5)
limitnumbernoMax results (default: 20)

contextgraph.impact_analysis

Who calls a method, function or type — "what calls X", "what breaks if I change X" — or, with direction: "callees", what it calls.

Only resolved calls are listed (confidence 0.8 and up, by default), from production code. Each call names its caller and the call site's file:line, plus the rung that resolved it. That includes calls made through an interface method the target implements, marked with what they went through.

The answer says how complete it is. Name-only guesses below the threshold and calls from tests are counted, with the argument that would list them, rather than mixed in. For a type, the answer covers calls to its constructor and members, and not calls between its own members.

ParameterTypeRequiredDescription
symbolstringone of the twoBy name: Type.member, member or Type. An ambiguous name answers with its candidates.
nodeIdstringone of the twoA node id; one with a wrong parameter list resolves like a name
directionstringnocallers (default) or callees
minConfidencenumbernoLowest confidence listed (default 0.8; 0.4 also lists name-only guesses)
includeTestsbooleannoList calls from test code too (default false)
limitnumbernoMax calls rendered

contextgraph.trace

Calls followed several hops in one call, returned as a tree with each hop's file:line.

Callers (the default) walk up to the entry points that end up calling the start node. By default those are methods or types whose name ends in ViewModel, Presenter, Fragment, Activity, Controller or Screen. The answer names the entry points reached, the branches that end with no caller, and what was cut at the depth limit.

Callees walk down from a method or a whole type. Set entryPoints to what you are looking for, such as Api$ for the endpoints a ViewModel can reach, and only the paths that reach it are shown.

Calls through use-case holders, invoke operators and interface methods are followed. Wiring that is not a call (dependency-injection multibindings, reflection) is not, and the answer says so.

ParameterTypeRequiredDescription
symbolstringone of the twoWhere to start, by name: Type.member, member or Type
nodeIdstringone of the twoWhere to start, by node id
directionstringnocallers (default) or callees
depthnumbernoMax hops (default 5, at most 8)
entryPointsstringnoRegex on a method's or its type's name where the walk stops; for callees, the target to reach
minConfidencenumbernoLowest call confidence followed (default 0.8)
includeTestsbooleannoFollow calls from test code too (default false)

contextgraph.related_files

Return all source file paths associated with a node via provenance records.

contextgraph.build_context

Given a task description, searches the graph, expands neighborhoods, and returns a ranked set of nodes and edges relevant to the task — pointers rather than source. For a question you want answered, contextgraph.explore is the better call.

ParameterTypeDefault
taskstring—
depthnumber2

contextgraph.generate_report

Generate GRAPH_REPORT.md and graph.html in the specified output directory.
